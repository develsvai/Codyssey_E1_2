# Python 기초 발표 자료

이 문서는 Python을 처음 접하는 사람도 이해할 수 있도록 작성한 발표용 정리 자료입니다. 예시는 현재 레포(`Codyssey_E1_2`)의 코드 구조와 동작을 참고했습니다.

---

## 1. 컴파일러와 인터프리터

### 1-1. 컴파일러란?
- 컴파일러는 사람이 쓴 코드를 한 번에 기계가 이해하는 언어(보통 기계어)로 바꾸는 프로그램입니다.
- 예를 들어 C 언어는 `gcc` 같은 컴파일러가 소스 코드를 읽고 `.exe`나 실행 가능한 파일을 만듭니다.
- 컴파일이 끝나면 프로그램을 실행할 때는 다시 번역할 필요 없이, 만든 실행 파일을 바로 실행합니다.

### 1-2. 인터프리터란?
- 인터프리터는 코드를 한 줄씩 읽어 실행하는 프로그램입니다.
- Python은 인터프리터 방식으로 동작합니다. 즉, 작성한 `.py` 파일을 바로 실행하면 Python 인터프리터가 코드를 순서대로 해석하고 처리합니다.
- 이 방식은 "바로 실행해서 결과를 확인"하기 쉬운 장점이 있습니다.

### 1-3. 차이점 쉽게 정리하기
- 컴파일러: 먼저 번역하고 실행한다.
  - 장점: 실행 속도가 빠르고, 결과 파일만 있으면 실행 가능.
  - 단점: 번역하는 시간이 필요하고, 번역 과정에서 오류를 고쳐야 한다.
- 인터프리터: 바로 한 줄씩 실행한다.
  - 장점: 수정 후 바로 실행해 볼 수 있어서 배우기 쉽다.
  - 단점: 실행할 때마다 해석해야 하므로 속도가 느릴 수 있다.

### 1-4. 레포 예시로 보기
- `main.py`를 직접 `python3 main.py`로 실행하면 Python 인터프리터가 `main.py`를 읽고 `QuizGame`, `QuizCli` 같은 클래스를 사용해 프로그램을 동작시킵니다.
- 이 과정에서 별도의 빌드(compile) 과정이 없습니다.

## 2. Python이라는 언어의 특징

### 2-1. 왜 Python은 배우기 쉬운가?
- 문법이 간단하고 읽기 쉬운 구조입니다.
- 들여쓰기를 사용해 블록을 구분하므로 코드가 자연스럽게 정리됩니다.
- `print`, `input`, `len` 같은 기본 기능이 바로 있어 실습하기 편합니다.

### 2-2. "런타임이 가벼운 이유"라고 말하는 경우
- Python은 실행 전에 별도의 컴파일 파일을 만들지 않고 곧바로 실행할 수 있기 때문에 개발 초기 단계에서 빠르게 시험해볼 수 있습니다.
- 작은 스크립트나 콘솔 프로그램을 만들 때, 다른 언어처럼 큰 도구 설치나 빌드 과정이 필요하지 않습니다.
- 대신 순수 실행 속도는 C나 Java보다 느릴 수 있습니다.

### 2-3. 버전 종속성
- Python은 버전별로 일부 문법과 표준 라이브러리가 다릅니다.
- 예를 들면 Python 3.6 이후에는 `f"{value}"` 문자열 포맷이 있고, Python 3.10 이후에는 `match` 문법이 추가되었습니다.
- 이 레포는 `README.md`에서 `Python 3.10 이상`을 권장하고 있습니다. 즉, 작성된 코드가 새로운 버전의 Python 문법이나 동작을 기대할 수 있다는 뜻입니다.
- 따라서 같은 Python이라고 해도 `python2`와 `python3`, 또는 `3.8`과 `3.11` 사이에 차이가 있을 수 있으므로 버전을 확인하는 습관이 중요합니다.

### 2-4. 자유로운 라이브러리 커뮤니티
- Python은 전 세계 개발자가 만든 라이브러리를 쉽게 설치해 사용할 수 있습니다.
- `pip` 같은 도구를 통해 데이터를 처리하거나 그래픽을 그리거나 웹을 만드는 라이브러리를 추가할 수 있습니다.
- 예를 들어 웹 개발에는 `Django`, 데이터 분석에는 `pandas`, 머신러닝에는 `scikit-learn` 같은 라이브러리가 있습니다.
- 이 레포는 표준 라이브러리만 사용하지만, 같은 언어로도 원하는 기능을 추가하기 쉽다는 점이 Python의 강점입니다.

## 3. C, Java와의 차이점

### 3-1. 작성 방법과 실행 방법
- C
  - `hello.c`를 작성하고 컴파일러로 번역한 뒤 실행 파일을 만듭니다.
  - 번역 후에는 별도의 Python 인터프리터가 필요하지 않습니다.
- Java
  - `Hello.java`를 작성하고 `javac`로 `.class` 바이트코드를 만듭니다.
  - 실행 시에는 Java 가상 머신(JVM)이 필요합니다.
- Python
  - `.py` 파일을 바로 실행하면서 Python 인터프리터가 코드를 해석합니다.

### 3-2. 문법과 구조
- C는 메모리를 직접 관리해야 할 수 있고, 변수 타입을 미리 선언해야 합니다.
- Java도 타입을 미리 선언하지만, 객체 지향 구조가 기본이며 클래스 기반입니다.
- Python은 타입 선언이 선택적이고, 문법이 상대적으로 간단합니다.
  - `int x = 10` 대신 `x = 10`으로 바로 쓸 수 있습니다.

### 3-3. 메모리 관리
- C는 직접 `malloc`, `free` 같은 함수를 쓰거나 포인터를 다뤄야 합니다.
- Java는 JVM이 자동으로 메모리를 관리하고, 필요 없는 객체를 가비지 컬렉터가 정리합니다.
- Python도 자동 메모리 관리를 합니다. 개발자는 메모리를 자세히 관리하지 않아도 됩니다.

### 3-4. 실행 속도와 이식성
- C는 컴파일된 네이티브 코드이므로 실행 속도가 빠릅니다.
- Java는 JVM 위에서 실행되므로 중간 정도 속도입니다.
- Python은 인터프리터로 실행되므로 상대적으로 느릴 수 있지만, 작은 프로그램이나 스크립트 작성에는 매우 빠른 개발 속도를 가집니다.
- Python은 운영체제에 맞는 Python 인터프리터만 설치되어 있으면 거의 그대로 실행할 수 있습니다.

### 3-5. 구체적 차이 한 줄 요약
- C: 빠른 기계어, 메모리 직접 제어, 컴파일 필요.
- Java: 클래스 기반 객체 지향, JVM 필요, 비교적 엄격한 타입.
- Python: 문법 단순, 동적 타입, 인터프리터 실행, 개발 속도 중심.

## 4. Python 객체 지향의 특성

### 4-1. Python에서는 "모든 것이 객체"
- 숫자, 문자열, 함수, 클래스도 모두 객체로 취급됩니다.
- 예를 들어 `Quiz` 클래스의 인스턴스는 객체이고, `quiz.question`처럼 객체의 속성을 읽을 수 있습니다.

### 4-2. 클래스는 설계도
- `core/models.py`의 `Quiz` 클래스는 퀴즈 문제 데이터를 어떻게 저장하고 검사할지 정의합니다.
- `GameState` 클래스는 게임 상태를 저장하는 객체의 틀입니다.
- `QuizGame` 클래스는 퀴즈 게임의 동작을 구현합니다.

### 4-3. 메서드와 속성
- 클래스 안에는 데이터를 저장하는 속성(`question`, `choices`, `answer`)과 동작을 정의하는 메서드(`is_correct`)가 있습니다.
- `def is_correct(self, answer: int) -> bool:`는 `Quiz` 객체가 정답인지 판단하는 동작입니다.

### 4-4. 상속과 다형성
- Python은 클래스 상속을 지원합니다. 이 레포에는 직접 사용하지 않았지만, 기본 개념은 다음과 같습니다.
  - 부모 클래스의 기능을 물려받아 새로운 클래스를 만들 수 있습니다.
- 다형성은 서로 다른 객체가 같은 이름의 메서드를 제공할 때, 같은 방식으로 사용할 수 있는 특성입니다.

### 4-5. 접근 제한이 약함
- Python에는 `private` 같은 강한 접근 제한이 없습니다.
- 관례적으로 `_private_value`처럼 이름 앞에 밑줄을 붙여 "이 속성을 내부에서만 쓰세요"라는 뜻을 전달합니다.
- 이 레포에서는 `self._state`와 같은 속성 이름을 사용해 내부 데이터를 숨기려는 의도를 보여줍니다.

### 4-6. 객체 지향을 쓰는 이유
- 관련된 데이터와 기능을 묶어서 관리하면 코드가 더 명확해집니다.
- 퀴즈 하나하나를 `Quiz` 객체로 보면, 질문과 정답과 선택지가 하나의 단위로 모입니다.
- 전체 게임 규칙은 `QuizGame`에 맡겨서 `Quiz` 객체가 자신의 역할만 하도록 분리할 수 있습니다.

## 5. PyInstaller로 만든 파일과 다른 언어 실행파일의 차이

### 5-1. PyInstaller가 하는 일
- Python 코드를 실행 파일로 묶을 때 `pyinstaller`는 다음을 함께 패키징합니다.
  - Python 인터프리터 실행 프로그램
  - 사용자가 작성한 `.py` 코드
  - 프로그램이 필요로 하는 Python 표준 라이브러리와 외부 라이브러리
- 결과물은 하나의 폴더나 하나의 실행 파일로 만들어질 수 있습니다.

### 5-2. 다른 언어 실행 파일과의 차이
- C/C++ 실행 파일
  - 실제 CPU가 바로 이해하는 기계어 코드로 번역되어 있습니다.
  - 별도의 Python 인터프리터가 필요 없습니다.
- Java 실행 파일(`.jar`)
  - 바이트코드로 번역되어 JVM에서 실행됩니다.
  - JVM이 있어야 동작합니다.
- PyInstaller 실행 파일
  - 실제로는 Python 인터프리터와 코드, 필요한 라이브러리가 함께 들어 있는 묶음입니다.
  - 실행하면 내장된 Python 인터프리터가 코드를 해석합니다.

### 5-3. 왜 크기가 큰가?
- PyInstaller로 만든 파일은 Python 인터프리터와 라이브러리까지 담으므로 용량이 커집니다.
- 작은 Python 코드 하나만 있어도 실행 파일은 몇십 MB가 될 수 있습니다.
- 반면 C로 만든 간단한 프로그램은 몇 MB 또는 몇 KB 수준이 될 수 있습니다.

### 5-4. 실행 방식의 차이
- C 실행 파일은 운영체제에 바로 전달되어 CPU가 직접 실행합니다.
- PyInstaller 실행 파일은 내부의 Python 인터프리터가 프로그램 코드를 읽고 실행합니다.
- 따라서 PyInstaller 실행 파일은 "실행 파일처럼 보이지만, 내부적으로 Python 코드를 해석하는 Python 런타임을 포함한 패키지"입니다.

## 6. 관심사(Concern)란 무엇인가?

### 6-1. 관심사의 뜻
- 관심사란 우리가 코드에서 집중해야 할 한 가지 주제나 기능입니다.
- 예를 들어 이 레포에서는 다음과 같은 관심사가 있습니다.
  - 사용자와 대화를 나누는 부분: `cli/app.py`
  - 게임 규칙과 점수 계산: `core/game.py`
  - 데이터 저장과 불러오기: `core/storage.py`
- 서로 다른 관심사를 나누면 코드가 더 깔끔하고 이해하기 쉬워집니다.

### 6-2. 관심사 분리의 예
- `QuizCli`는 화면에 메뉴를 보여주고 입력을 받는 역할만 합니다.
- `QuizGame`은 퀴즈 점수 계산과 상태 관리를 합니다.
- `JsonStateRepository`는 파일 입출력만 담당합니다.
- 이렇게 역할을 나누면 한 부분을 바꿀 때 다른 부분에 미치는 영향이 줄어듭니다.

## 7. 기능/역할로 부여하는 것과의 차이

### 7-1. 기능과 역할은 무엇인가?
- 기능은 코드가 실제로 하는 일입니다.
- 역할은 그 코드가 전체 시스템에서 맡는 위치입니다.

### 7-2. 차이를 쉽게 보기
- 기능 중심으로 보면 `QuizGame`은 "점수를 계산하는 기능"을 합니다.
- 역할 중심으로 보면 `QuizGame`은 "퀴즈 게임의 규칙과 상태를 책임지는 역할"을 합니다.
- 즉, 기능은 "무엇을 하는지", 역할은 "어떤 책임을 지는지"를 말합니다.

### 7-3. 왜 역할이 중요할까?
- 같은 기능이라도 어디에 두느냐에 따라 설계가 달라집니다.
- 예를 들어 입력 처리 기능을 `QuizGame`에 넣으면 `QuizGame`이 너무 많은 일을 하게 됩니다.
- 대신 `QuizCli`에 넣으면 화면 책임과 게임 책임이 분리되어 설계가 더 명확해집니다.

## 8. 클래스는 재료, 중요한 것은 관점

### 8-1. 볶음밥/삼각김밥/비빔밥 비유
- 밥은 모두 같은 재료입니다.
- 그러나 볶음밥, 삼각김밥, 비빔밥은 각각 다른 결과물입니다.
- 프로그래밍에서도 클래스는 재료이고, 어떻게 사용하느냐가 더 중요합니다.

### 8-2. 클래스와 객체의 관점
- `Quiz` 클래스는 퀴즈 정보를 담는 재료입니다.
- 이 재료를 `QuizGame`에서 문제 풀기 용도로 사용할 수도 있고,
- 다른 프로그램에서는 퀴즈 출제 도구로 사용할 수도 있습니다.
- 중요한 것은 "클래스를 어떻게 설계하고 어떤 목적에 맞게 쓰느냐"입니다.

### 8-3. 설계 관점이 다르면 결과도 다르다
- 같은 `밥`(class)을 사용해도, 만드는 사람의 목적에 따라 다른 프로그램이 됩니다.
- `Quiz`가 단순히 데이터를 담는 역할일 수도 있고,
- `QuizManager`가 여러 퀴즈를 관리하는 역할이 될 수도 있습니다.
- 이처럼 클래스 설계는 재료 그 자체보다 그 재료를 어떤 관점으로 바라보는지가 중요합니다.

## 9. 발표 정리 핵심 문장

- Python은 인터프리터 방식이며, 코드를 바로 실행해 볼 수 있어 배우기 쉽습니다.
- Python은 문법이 간단하고, 많은 라이브러리 커뮤니티 덕분에 기능 확장이 쉽습니다.
- C와 Java는 컴파일 과정이 필요하거나 VM이 필요하지만, Python은 인터프리터 실행으로 개발 속도가 빠릅니다.
- Python 객체 지향의 핵심은 "모든 것이 객체"이고, 클래스는 데이터를 담고 동작을 묶는 설계도입니다.
- PyInstaller로 만든 실행 파일은 실제 네이티브 코드가 아니라 Python 인터프리터와 코드, 라이브러리를 함께 묶은 패키지입니다.
- 관심사는 코드가 집중해야 할 책임이고, 기능/역할을 나누면 유지보수가 쉬워집니다.
- 클래스는 재료일 뿐이고, 중요한 것은 그 재료를 어떤 방법으로, 어떤 목적을 위해 사용하는가입니다.

## 10. 발표 준비 팁

- 질문자가 Python을 모른다면, 먼저 "코드를 읽어서 컴퓨터가 하는 일을 알려주는 것"이라는 기본 개념을 짧게 설명하세요.
- `main.py` 실행 흐름(`main -> QuizGame -> QuizCli`)을 그림으로 간단히 보여주면 이해가 빠릅니다.
- "클래스는 설계도"와 "객체는 실제 물건" 비유를 함께 쓰면 좋습니다.
- PyInstaller 부분은 "겉보기에는 실행 파일이지만 내부에는 Python이 함께 들어 있다"는 점을 분명히 말하세요.
- 마지막에 `관심사 분리`와 `재료 vs 관점` 비유로 설계를 마무리하면 기억에 남습니다.
