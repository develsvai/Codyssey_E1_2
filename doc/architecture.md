# 설계 구조 문서

## 목적

이 문서는 Python 콘솔 퀴즈 게임 미션의 현재 설계 구조를 고정하고, 이후 구현 작업에서 지켜야 할 의존 방향과 역할 분리를 명확히 하기 위해 작성한다.

현재 설계의 핵심 원칙은 다음과 같다.

- 사용자 입출력은 `cli` 패키지에서만 처리한다.
- 게임 규칙, 퀴즈 모델, 저장 경계는 `core` 패키지에 둔다.
- `core`는 `cli`를 import하지 않는다.
- `main.py`는 객체를 조립하고 실행을 시작하는 진입점 역할만 한다.
- 저장 구현은 추상 인터페이스 뒤에 둬서 core 로직과 파일 저장 방식을 분리한다.

## 현재 파일 구조

```text
main.py
core/
  __init__.py
  interfaces.py
  models.py
  game.py
  storage.py
cli/
  __init__.py
  app.py
README.md
.gitignore
state.json
```

`state.json`은 프로그램 실행 중 생성되는 런타임 데이터 파일이다. 현재 `.gitignore`에 포함되어 있어 저장소에는 커밋하지 않는다.

## 의존 방향

```text
main.py
  -> cli.app
  -> core.game
  -> core.storage

cli.app
  -> core.game

core.game
  -> core.interfaces
  -> core.models

core.storage
  -> core.interfaces
  -> core.models

core.models
  -> 표준 라이브러리
```

금지할 의존 방향은 다음과 같다.

```text
core -> cli
core.models -> core.game
core.models -> core.storage
```

## 패키지별 책임

### `main.py`

앱의 조립 지점이다. `JsonStateRepository`, `QuizGame`, `QuizCli`를 생성하고 CLI 실행을 시작한다.

현재 역할:

- `state.json` 경로 결정
- 저장소 구현체 생성
- 게임 객체 생성
- CLI 객체 생성
- 프로세스 종료 코드 반환

### `core.models`

도메인 데이터를 표현한다.

현재 클래스:

- `Quiz`: 개별 퀴즈의 문제, 선택지 4개, 정답 번호를 가진다.
- `GameState`: 퀴즈 목록과 최고 점수를 가진다.

`Quiz`는 생성 시 다음 불변 조건을 검증한다.

- 문제는 빈 문자열일 수 없다.
- 선택지는 정확히 4개여야 한다.
- 선택지는 빈 문자열일 수 없다.
- 정답 번호는 1부터 4 사이여야 한다.

### `core.interfaces`

core가 외부 저장 방식에 의존하지 않도록 추상 경계를 정의한다.

현재 인터페이스:

- `StateRepository`
  - `load() -> GameState | None`
  - `save(state: GameState) -> None`

### `core.storage`

파일 저장 구현체를 둔다.

현재 클래스:

- `JsonStateRepository`

현재 역할:

- 프로젝트 루트의 `state.json` 읽기
- JSON 데이터를 `GameState`와 `Quiz`로 변환
- `GameState`를 JSON 형태로 저장
- 파일 없음, JSON 손상, 타입 오류, 스키마 오류가 있을 때 `None` 반환

후속 구현에서 보강할 점:

- 파일 손상 또는 읽기 오류가 발생했음을 CLI에 안내할 수 있는 결과 타입 또는 상태 플래그 추가 검토
- 저장 실패 시 사용자에게 더 구체적인 안내 제공

### `core.game`

게임 상태와 유스케이스를 조율한다.

현재 클래스:

- `QuizGame`

현재 역할:

- 저장된 상태 불러오기
- 저장된 상태가 없으면 기본 퀴즈 5개 사용
- 퀴즈 목록 조회
- 퀴즈 추가 메서드 제공
- 최고 점수 갱신 메서드 제공
- 현재 상태 저장

후속 구현에서 보강할 점:

- 퀴즈 풀이 결과 계산을 core에 둘지, CLI와 분담할지 확정
- 점수 단위를 정답 개수로 유지할지 100점 환산 점수로 확장할지 결정

### `cli.app`

사용자와 직접 만나는 콘솔 어댑터다.

현재 클래스:

- `QuizCli`

현재 역할:

- 메뉴 출력
- 메뉴 번호 입력
- 빈 입력, 숫자 변환 실패, 범위 밖 입력 처리
- `KeyboardInterrupt`, `EOFError` 발생 시 저장 후 안전 종료
- 퀴즈 목록 출력
- 최고 점수 출력
- 종료 시 저장

후속 구현에서 보강할 점:

- 메뉴 1번 퀴즈 풀기 실제 구현
- 메뉴 2번 퀴즈 추가 실제 구현
- 정답 번호 입력의 공통 검증 함수 분리
- 손상된 `state.json` 복구 안내 메시지 추가

## `state.json` 스키마

현재 저장 스키마는 다음 형태를 기준으로 한다.

```json
{
  "quizzes": [
    {
      "question": "Python의 창시자는?",
      "choices": ["Guido", "Linus", "Bjarne", "James"],
      "answer": 1
    }
  ],
  "best_score": 0
}
```

필드 규칙:

- `quizzes`: 퀴즈 객체 배열
- `quizzes[].question`: 문제 문자열
- `quizzes[].choices`: 선택지 4개를 담은 문자열 배열
- `quizzes[].answer`: 1부터 4 사이의 정답 번호
- `best_score`: 최고 점수 또는 최고 정답 수

## 미션 조건 부합성 점검

이 표는 현재 커밋 기준의 상태를 나타낸다. 미션 최종 제출 기준이 아니라, 현재 구현 진행도를 표시한다.

| 미션 조건 | 현재 상태 | 근거 | 후속 작업 |
| --- | --- | --- | --- |
| Python 콘솔 프로그램 1개 | 부분 충족 | `main.py` 실행 시 콘솔 메뉴가 출력된다. | 퀴즈 풀기/추가를 실제 동작으로 완성해야 한다. |
| 메뉴에서 퀴즈 출제/등록/목록/점수/종료 선택 | 부분 충족 | 메뉴 1~5번은 존재한다. 목록, 점수, 종료는 기본 동작한다. | 1번 퀴즈 풀기와 2번 퀴즈 추가를 구현해야 한다. |
| 퀴즈 풀기 기능 | 미충족 | 현재 안내 메시지만 출력한다. | `퀴즈 풀이 기능 완성` Task에서 구현한다. |
| 퀴즈 추가 기능 | 미충족 | 현재 안내 메시지만 출력한다. | `퀴즈 추가와 JSON 저장 안정화` Task에서 구현한다. |
| 퀴즈 목록 기능 | 부분 충족 | 기본 퀴즈 5개 제목 출력이 가능하다. | 추가된 퀴즈 목록 유지와 빈 목록 처리를 최종 검증해야 한다. |
| 점수 확인 기능 | 부분 충족 | 최고 점수 출력은 가능하다. | 퀴즈 풀이 후 최고 점수 갱신 흐름을 연결해야 한다. |
| 본인 선택 주제 퀴즈 5개 이상 | 충족 | Python, Git, JSON 기초 주제로 기본 퀴즈 5개가 있다. | 최종 README에 주제 선정 이유를 더 분명히 적는다. |
| 종료 후 추가 퀴즈와 최고 점수 유지 | 부분 충족 | `JsonStateRepository`와 `state.json` 저장 구조는 있다. | 퀴즈 추가와 점수 갱신 기능을 연결해 재시작 검증이 필요하다. |
| 최소 2개 이상의 클래스 | 충족 | `Quiz`, `GameState`, `QuizGame`, `JsonStateRepository`, `QuizCli`가 있다. | 없음. |
| 기능별 메서드 분리 | 부분 충족 | 메뉴, 저장, 목록, 모델 변환 등이 분리되어 있다. | 퀴즈 풀이/추가 입력 로직 구현 시 더 분리해야 한다. |
| `state.json` UTF-8 저장/불러오기 | 부분 충족 | `core/storage.py`가 UTF-8로 읽고 쓴다. | 손상 파일 안내 메시지와 재시작 유지 검증이 필요하다. |
| 잘못된 숫자 입력 처리 | 부분 충족 | 메뉴 입력의 빈 값, 숫자 변환 실패, 범위 밖 숫자를 처리한다. | 정답 입력과 퀴즈 추가 입력에도 같은 기준을 적용해야 한다. |
| `KeyboardInterrupt`, `EOFError` 안전 종료 | 부분 충족 | 메뉴 입력 중 발생 시 저장 후 종료한다. | 퀴즈 풀이/추가 입력 중에도 동일하게 처리해야 한다. |
| 데이터 파일 없음/손상 처리 | 부분 충족 | 파일 없음/손상 시 기본 퀴즈로 실행 가능하다. | 손상 사실을 사용자에게 안내하는 흐름을 보강해야 한다. |
| README 필수 항목 | 부분 충족 | 개요, 주제, 실행 방법, 기능, 구조, 데이터 파일 설명이 있다. | 최종 기능 구현 후 실제 상태에 맞게 보강해야 한다. |
| GitHub 저장소 업로드 | 부분 충족 | `origin` 원격 저장소는 연결되어 있다. | `develop` 변경 push와 최종 URL 제출 확인이 필요하다. |
| 최소 10개 이상 의미 있는 커밋 | 미충족 | 현재 구현 관련 커밋 수가 10개 미만이다. | 기능 단위 Task마다 커밋을 추가해야 한다. |
| 브랜치 생성 및 병합 기록 | 부분 충족 | `develop` 브랜치에서 작업 중이다. | 최종적으로 main/master 병합 기록이 필요하다. |
| `clone`, `pull` 실습 기록 | 미충족 | 아직 별도 clone/pull 실습을 수행하지 않았다. | README/Git workflow Task에서 수행하거나 사용자 수행 항목으로 정리한다. |
| 제출 스크린샷 | 미충족 | 아직 캡처 산출물이 없다. | 실행 화면, 환경 설정, git log 스크린샷을 준비해야 한다. |

## 현재 결론

현재 설계 방향은 미션의 구조 요구사항에 잘 맞는다.

- 클래스 2개 이상 요구사항을 충족한다.
- `Quiz`와 `QuizGame` 중심 구조를 유지한다.
- CLI를 분리해 사용자 입출력과 core 로직의 경계를 명확히 했다.
- `StateRepository` 인터페이스로 저장소 구현을 분리했다.
- 기본 퀴즈 5개와 `state.json` 영속성 기반이 준비되어 있다.

다만 최종 미션 조건은 아직 충족하지 않는다. 현재 상태는 “설계와 기본 골격은 부합, 기능 완성은 진행 전”으로 보는 것이 정확하다.

다음 구현 우선순위는 다음과 같다.

1. 퀴즈 풀이 기능 완성
2. 퀴즈 추가 기능과 `state.json` 재시작 유지 검증
3. README 최종화와 Git workflow 제출 조건 정리
4. GitHub push, clone/pull 실습, 제출 스크린샷 준비
